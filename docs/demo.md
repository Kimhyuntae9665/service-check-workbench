# 생산실적 연결 오류 대표 시연

생산실적 조회 화면이 열리지 않는다는 신고를 받은 IT 담당자의 점검 흐름입니다. 포트 번호와 점검 상태는 실행 당시의 실제 근거에서 가져옵니다. 회사의 실제 고객 시스템은 사용하지 않았습니다.

## 1. 연결 오류 점검해보기

![대표 시연 시작 화면](screenshots/demo-intro.jpg)

첫 화면의 버튼 하나로 새 장애 접수, 로컬 연결 포트 오류 재현, MCP 도구 점검을 수행합니다. 기존 기록을 삭제하지 않습니다. 샘플 환경은 공유되므로 과거의 정상 확인은 만료될 수 있습니다.

## 2. 원인 확인

![실제 포트 오류 결과](screenshots/demo-failure.jpg)

서비스 기동과 DB 조회는 통과하지만 HTTP 접속과 생산실적 조회는 실패합니다. 실제 서비스 실행 포트와 접속 설정 포트가 다르다는 근거를 보여줍니다. **실행 근거와 관측 시각 보기**를 펼치면 HTTP 오류와 SQL 조회 결과를 볼 수 있습니다.

## 3. 포트 수정하고 다시 확인

![실제 복구 재검증 결과](screenshots/demo-recovered.jpg)

로컬 샘플 환경의 연결 설정을 복구하고 같은 네 점검을 다시 실행합니다. 서버가 기동되어 있다는 이유만으로 해결 완료로 처리하지 않습니다. 현재 환경의 필수 항목이 모두 통과한 재검증이 필요합니다.

## 4. 해결 가이드 저장

![대표 시연의 해결 가이드](screenshots/demo-guide.jpg)

가이드에는 실패 당시의 원인과 주소, 수정 내용, 실제 재검증 결과가 함께 남습니다. **작업대 보기**에서 전체 실행 이력과 상세 근거로 이동할 수 있습니다.

## 구현과 실행 범위

- 기본 시연은 규칙으로 실제 MCP 도구를 호출합니다. 생성된 LLM 답변이 아닙니다.
- 실제 OpenAI API 실행은 키 미설정으로 아직 확인하지 않았습니다. 키 설정 후 npm run evidence:llm으로 별도 검증할 수 있습니다.
- 여러 운영 서버·고객 데이터·사용자 권한을 연결한 상용 모니터링 서비스는 아닙니다.

실제 브라우저 점검 결과와 실패 경로는 [검증 기록](validation.md)에 남겼습니다.

모바일에서도 세 단계 완료와 가이드 저장을 확인했습니다. [모바일 첫 화면](screenshots/demo-mobile-intro.jpg), [모바일 시연 전체](screenshots/demo-mobile.jpg). 브라우저 시연 직후 저장된 실제 Run·Guide의 원본 API 스냅샷은 [demo-evidence.json](demo-evidence.json)입니다. 외부 LLM 실행 기록과는 구분합니다.
