# 검증 기록

검증일: 2026-10-02 · Windows · Node.js v24.19.0. 실제 실행 결과와 아직 확인하지 않은 범위를 함께 기록했습니다.

**npm run check 통과: 타입 검사, 자동 테스트 10/10, Vite production build.**

| 확인 항목      | 결과                                                                              |

| 초기 샘플      | 장애 1건, 실행 0건, 가이드 0건. 점검 실적을 미리 만들어 넣지 않음                 |

## Superpowers 설치 후 추가 검증

독립 코드 리뷰에서 화면의 수정 전 실패 개수가 첫 실패를 기준으로 남는 표시 오류를 찾았습니다. 같은 장애에서 서비스 중지(실패 3개) → 포트 오류(실패 2개) → 정상 재검증을 실제 화면으로 실행했습니다. 수정 전 화면은 3개를 표시했고, 수정 후 같은 기록을 다시 열어 최근 실패인 2개를 표시하는 것을 확인했습니다. 저장된 가이드의 원인과 재현 연결 주소도 최근 포트 오류와 일치했습니다.

수정 후 npm run check를 새로 실행해 타입 검사·테스트 10/10·production build가 모두 통과했습니다. 브라우저 콘솔 오류·경고는 없었고, 후속 독립 리뷰에서 기존 표시 오류가 해소됐으며 새 Critical/Important 문제는 발견되지 않았습니다. [수정된 비교 화면](screenshots/comparison.jpg), [최근 원인으로 저장한 가이드](screenshots/latest-cause-guide.jpg).

## SQL 실행계획

명령: **npm run query-plan**. 앱의 .data를 열지 않는 독립 메모리 DB에 합성 장애 100건·실행 10,000건을 생성했습니다. 선택한 장애의 이력은 100건입니다. 두 실행 모두 enable_seqscan=on으로 확인했습니다.

| 구분      | 실제 계획                                   | 단일 실행 시간 |
| --------- | ------------------------------------------- | -------------- |
| 인덱스 전 | Seq Scan → Sort, 필터에서 9,900건 제외      | 4.002ms        |
| 인덱스 후 | Bitmap Index Scan → Bitmap Heap Scan → Sort | 0.551ms        |

사용한 인덱스는 runs(incident_id, (data->>'startedAt'))입니다. 이 실험에서는 **필터를 인덱스로 찾았지만 Sort는 남았습니다.** 값은 한 번의 로컬 실행이며 표본 평균·운영 처리량·보장된 개선율이 아닙니다. 원문과 재현 스크립트: [query-plan.json](query-plan.json), [scripts/query-plan.ts](../scripts/query-plan.ts).

## 장애 재현 실행 기록

**npm run benchmark**는 실제 MCP·로컬 HTTP·SQL로 세 장애 각각 실패 진단 → 정상 재검증 → 가이드 생성까지 실행합니다. 각 흐름의 MCP 호출은 10회이며, 결과 파일에 실측 소요시간을 남겼습니다. 로컬 샘플 2건을 쓰는 시연 환경 수치이므로 운영 성능으로 설명하지 않습니다. [원문 JSON](smoke-report.json).

## 아직 검증하지 않은 범위

- 실제 OpenAI 모델의 응답·권한·과금: API 키 미제공. 주입 gateway 테스트는 실제 provider 호환성 증거를 대신하지 않음
- 실제 기업 서비스·고객 데이터·외부 MCP 서버·클라우드 배포
- PostgreSQL 네이티브 인증·네트워크 프로토콜: PGlite이며 권한 장애는 모의 앱 게이트
- 여러 사용자 환경의 인증·권한·대규모 처리량·주기 모니터링

이 프로젝트는 로컬 시연 앱입니다. 자동 테스트와 실제 브라우저 점검이 끝났다는 사실을 상용 운영 완료로 확대하지 않습니다.

## 대표 시연 통합 검증

대표 시연 버튼으로 새 장애 접수 → 실제 포트 오류 진단 → 연결 설정 복구·재검증 → 해결 가이드 저장을 브라우저에서 실행했습니다. 수정 전 서비스 기동·DB 조회는 통과, HTTP 연결·생산실적 조회는 실패했습니다. 수정 후 같은 네 항목이 모두 통과했고, 저장한 가이드에 실제 실패 실행과 재검증 근거가 연결됐습니다. 상세 안내는 [대표 시연](demo.md)입니다.

GPT-6 Astra 독립 리뷰에서 환경 변경 후 점검 요청이 실패하면 이전 정상 표시가 남을 수 있는 문제를 찾았습니다. 시나리오 변경 응답을 즉시 반영하고, 새 접수 선택·실패 후 새로고침·복구 전 정상 표시 만료를 적용했습니다. 임시 로컬 HTTP 프록시는 POST /runs만 503으로 응답하고 다른 요청은 실제 앱으로 전달했습니다. 다음을 실제 화면에서 확인했습니다.

| 조건 | 관측 결과 |
| --- | --- |
| 완료된 시연에서 새 시연 시작, 환경 변경 성공·원인 점검 요청 실패 | 새 접수로 전환, 완료 단계 0개, 네 항목 미실행, 실패 메시지 표시 |
| 실제 원인 확인 뒤 정상 환경 복구 성공·재검증 요청 실패 | 원인 단계만 완료, 현재 상태 재확인 안내, 가이드 저장 버튼 없음 |

[요청 실패 화면](screenshots/demo-request-failure.jpg). 검증 프록시와 임시 실패 조건은 종료·해제했습니다. 후속 독립 소스 리뷰에서 해당 문제가 해소됐고 새 Critical/Important 지적은 없었습니다.

수정 후 npm run check가 exit 0으로 완료됐습니다. 타입 검사, 자동 테스트 10/10(실패·건너뜀 0), Vite 빌드 통과. 1280×900 화면에서 전체 시연을 확인했고, 390×844 모바일에서 문서 너비·콘텐츠 너비가 모두 375px로 가로 넘침이 없었습니다. [모바일 시연](screenshots/demo-mobile.jpg).

실제 LLM 증거 명령 npm run evidence:llm도 실행했습니다. 현재 키 미설정으로 외부 요청을 하지 않고 종료했으며 docs/llm-evidence.json을 생성하지 않았습니다. 이는 실제 모델 실행 성공 증거가 아닙니다. 키가 설정되면 독립 메모리 DB에서 실제 OpenAI 응답의 요청 ID·모델·사용량과 포트 오류·재검증·가이드 결과를 기록하도록 구현했습니다.

모바일에서도 대표 시연 시작·복구·가이드 저장을 끝까지 실행해 완료 단계 3개와 가로 넘침 없음, 브라우저 오류·경고 없음([])을 확인했습니다. 최종 API 스냅샷에서 가이드 sourceRunId와 실패 Run, verificationRunId와 통과 Run이 일치합니다. [원문](demo-evidence.json).
